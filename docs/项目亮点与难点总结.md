# 项目亮点与难点总结

> 文档版本：2026-08-13（实测验证版）｜ 每个亮点均标注"可验证事实"，面试可直接引用

## 一、技术亮点（按面试价值排序）

### 1. RAG 全流程闭环（基础）
文档 → 分块 → 向量化 → 检索 → Prompt → 生成 + 来源引用。
**可验证**：HashMap 问答实测 5.9s，来源片段 score 1.0 精准命中，回答逐条引用。

### 2. 混合检索（Milvus 2.5 BM25 Function）
稠密向量（语义）+ 稀疏向量（关键词）双路召回，`alpha=0.7` 加权融合。
**亮点**：Milvus 2.5 服务端内置 BM25（`FunctionType.BM25` + `EmbeddedText`），Java 端零 BM25 计算代码。
**面试话术**：*"向量检索对精确匹配（编号/型号）不敏感，所以加 BM25 稀疏路兜底；alpha 用测试集调"*。

### 3. Agentic 化（Function Calling + ReAct）
工具定义（名称/描述/参数 schema）→ 模型返回结构化 `tool_calls` → 执行回填 → 循环。
**可验证**：`/api/agent/ask`"有多少篇文档"实测 3.9s 真实调用统计工具回答"2 篇文档"。
**面试话术**：*"tool_calls 是模型训练对齐的原生格式，比让模型输出 JSON 稳定；assistant 消息必须原样回填否则 400"*。

### 4. 多 Agent 编排 + 反思
主管路由分派（文档/数据/报告），HYBRID 组合回答，`CriticService` LLM 评审不合格带意见重写（次数硬上限）。
**可验证**：orchestrate 实测路由准确（列表问题→STATS，3.4s）。

### 5. 三层降级矩阵（高可用设计）
Rerank 失败→原分排序；混合检索失败→纯稠密；记忆/评审失败→静默；LLM 不可用→熔断(5次/60s)。
**面试话术**：*"所有外部依赖都有降级路径，主链路永远可用"*。

### 6. 长期记忆
独立 `qa_memory` collection，问答对入库、score>0.5 召回；**旁路增强静默降级**（失败不影响主流程）。

### 7. JWT + ThreadLocal 数据隔离
拦截器验签 → UserContext 持有 userId → 全链路（含工具内）按用户过滤；`afterCompletion` 清理防泄漏。
**面试话术**：*"ThreadLocal 为什么用 afterCompletion 清理？因为 postHandle 在异常时不执行"*。

### 8. 安全细节
BCrypt 密码、统一登录错误提示（防枚举）、XSS 防护（前端 v-html 禁用）、JWT 24h 过期。

### 9. 工程化
模块化单体、`@ConfigurationProperties` 配置外置（RagProperties）、全局异常（BusinessException→Result）、Knife4j 文档、评估集 + 指标埋点。

## 二、难点与攻克（真实踩坑，面试"讲讲你遇到的坑"）

| # | 难点 | 现象 | 根因 | 解决方案 |
|---|------|------|------|----------|
| 1 | **Milvus 2.4→2.5 升级兼容** | 检索报 `Search target vector type is illegal` | 2.5 SDK 要求 FloatVector 查询向量 `List<Float>`（2.4 可传 `float[]`） | `toVectorList()` 转换（search/searchMemory） |
| 2 | **SDK 依赖变化** | 编译报 fastjson 找不到 | 2.5 SDK 不再传递 fastjson（改用 Gson），`InsertParam.withRows` 签名从 fastjson JSONObject 变 Gson JsonObject | pom 显式声明 fastjson 1.2.83 + insertVectors 改 Gson |
| 3 | **DeepSeek 思考模型 Function Calling** | Agent 工具调用 400 `missing field type` / `reasoning_content must be passed back` | v4-flash 思考模式：消息须带 `type`；回填 assistant 消息必须含 `reasoning_content` + 完整 tool_calls（含 index） | `readTree` 取原始 JSON 原样回填 + 消息补 `type` 字段 |
| 4 | **数据迁移陷阱** | 上传报 `Unknown column 'category'` | 旧 MySQL volume 表结构缺列（init.sql 有但 `IF NOT EXISTS` 不重建） | 执行 migration 脚本 `ALTER TABLE`；文档补充说明 |
| 5 | **认证排除误伤** | `/api/auth/me` 恒 400 | 拦截器排除 `/api/auth/**` 把 me 也放行（UserContext 未设置） | 精确排除 login/register |
| 6 | **输入校验缺失** | 空问题返回 200 | `@RequestBody String` 接整个 JSON 无法校验字段 | DTO 化 + 空校验 |
| 7 | **LLM 幻觉（路由误判）** | "有哪些文档"被判 DOCUMENT，检索无关内容后**编造文档列表** | 路由 prompt 对统计/列表意图识别不准 | 增强路由 prompt（列出/多少/有哪些→STATS） |
| 8 | **阈值穿透** | 低相关重复文本 score>0.35 未被过滤 | min-score 未按测试集校准 | 可接受（LLM 诚实拒答）；上线前校准阈值 |
