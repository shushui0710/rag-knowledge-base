# RAG 智能知识库问答平台 —— 技术亮点与架构设计

> **面向对象**：央国企技术岗面试官
> **一句话介绍**：一个基于 RAG（检索增强生成）的企业级智能知识库问答平台，支持文档入库、语义检索、大模型问答，并演进为 Agentic RAG——通过 Function Calling 让助手自主决策，配合混合检索、重排、记忆与反思等增强组件。

---

## 一、系统架构

```
                          ┌──────────────────────────────────────────┐
                          │              前端 Vue3 :5173              │
                          └────────────────┬─────────────────────────┘
                                           │ Axios + JWT(Bearer)
                                           ▼
┌──────────────────────────────────────────────────────────────────────────┐
│              Spring Boot 后端 :18080（模块化单体，5 大模块）                │
│  auth(认证) / document(文档) / chat(问答) / agent(Agent) / rag(检索增强)  │
│  JwtInterceptor ── UserContext(ThreadLocal) 持有当前用户，全链路数据隔离    │
└──────────────────────┬──────────────────────┬───────────────────────────┘
                       ▼                      ▼
        ┌─────────────────────────┐  ┌──────────────────────────┐
        │ 离线入库（数据管道）      │  │ 在线问答（RAG/Agent 链路） │
        └─────────────────────────┘  └──────────────────────────┘
   MinIO(文件) → PDFBox/POI(解析)     提问 → 查询改写 → 混合检索
   → 滑动窗口分块 → 智谱Embedding      → Rerank → Prompt → DeepSeek
   → Milvus 2.5(稠密+BM25稀疏)         Agent 模式：ReAct + 工具调用
```

### 在线链路（三档能力）

| 接口 | 链路 | 适用 |
|------|------|------|
| `/api/chat/ask` | 改写 → 混合检索(稠密+BM25) → Rerank → 生成 | 普通知识问答 |
| `/api/agent/ask` | 意图路由 → ReAct 循环（Function Calling 调工具） | 需要查统计/列表的问题 |
| `/api/agent/orchestrate` | 路由 → 多 Agent 分派（文档/数据/报告）→ HYBRID 组合 → 反思重写 | 复杂综合问题 |

## 二、技术选型理由（面试速答）

| 选型 | 理由 |
|------|------|
| **模块化单体**（非微服务） | 求职项目规模无需分布式开销；模块边界清晰，为未来演进预留路径；央国企正从微服务回退到模块化单体 |
| **MyBatis-Plus**（非 JPA） | 国内生态主流、SQL 完全可控、LambdaQueryWrapper 动态查询、无 N+1 |
| **Milvus 2.5**（非 ES/FAISS） | 开源向量库，支持稠密+稀疏（BM25 Function 内置）、亿级向量毫秒检索；2.5 起服务端自动 BM25 分词 |
| **智谱 embedding-3**（2048 维） | 中文效果好，API 简单 |
| **DeepSeek** | OpenAI 兼容格式、性价比高（deepseek-v4-flash） |

## 三、技术亮点（11 个，面试话术见速记卡）

### 亮点 1-6：RAG 基础
1. **RAG 在线/离线全流程**：文档 → 分块 → 向量化 → 检索 → Prompt → 生成 + 来源引用
2. **滑动窗口分块**（512 字 + 64 重叠）：保证语义完整性，避免截断
3. **查询改写**：口语 → 检索词；**检索用改写、回答用原问**（防丢意图）
4. **混合检索**（Milvus 2.5 BM25 Function）：稠密(语义) + 稀疏(关键词) 双路召回，`alpha` 加权融合
5. **Rerank 精排**：召回 20 → 精排 5（交叉编码，准但慢，只精排少量）
6. **来源引用**：回答附带文档来源，可追溯、可验证

### 亮点 7-11：Agentic 与工程化
7. **Function Calling**：工具定义（名称/描述/参数 schema）传给模型，模型返回结构化 `tool_calls`——比"让模型输出 JSON"稳定
8. **ReAct 循环**：思考→行动→观察→再思考，≤5 轮；**assistant(tool_calls) 必须原样回填**（漏了必报 400）
9. **多 Agent 编排**：主管路由分派（文档/数据/报告），每 Agent 决策空间小、Prompt 聚焦
10. **三层降级矩阵**（高可用设计）：Rerank 失败→原分排序；混合检索失败→纯稠密；记忆/评审失败→静默放行；LLM 挂了→熔断兜底
11. **工程化**：模块化单体 + `@ConfigurationProperties` 配置外置 + `@Bean` 依赖注入 + ThreadLocal 上下文 + 全局异常处理（BusinessException → Result）

## 四、Agentic RAG 演进路线（5 阶段，均可讲演进理由）

```
阶段1 增量更新与删向量   → 保证数据一致（先删旧再建新）
阶段2 检索质量优化       → 混合检索 + 改写 + 重排（召回率↑ 精度↑）
阶段3 Agentic 核心       → 工具抽象 + Function Calling + ReAct + 意图路由
阶段4 多 Agent 与认知    → 分工协作 + 长期记忆 + 反思重写（Self-Correct）
阶段5 工程化收尾         → 评估集 + 指标观测 + Embedding 缓存 + 熔断
```

面试话术：*"我先用朴素 RAG 跑通，再按'检索质量 → 自主决策 → 认知增强 → 工程化'的顺序演进，每一步都先想清楚解决什么问题、怎么验证效果。"*

## 五、数据安全与并发

- **认证**：JWT（HS256）+ BCrypt 密码加密；拦截器统一验签
- **隔离**：`UserContext(ThreadLocal)` 持有 userId，查询/工具全部按用户过滤；`afterCompletion` 清理防泄漏
- **并发**：Embedding 缓存 ConcurrentHashMap（上限 5000）、记忆主键 AtomicLong、工具注册表 double-check 懒加载
