# 项目技术架构说明

> 文档版本：2026-08-13（实测验证版）｜ 项目：RAG 智能知识库问答平台

## 一、项目定位

企业级智能知识库问答平台：文档上传 → 解析分块 → 向量化入库 → 语义检索 → 大模型生成，并演进为 **Agentic RAG**（Function Calling 工具调用 + ReAct 循环 + 多 Agent 编排 + 记忆与反思）。

## 三、核心链路（三条可演示路径）

| 路径 | 链路 | 实测耗时 |
|------|------|----------|
| 普通问答 `/api/chat/ask/{sessionId}` | 查询改写 → 混合检索(稠密+BM25，召回20) → Rerank(精排5) → Prompt → DeepSeek | 5.3~5.9s |
| Agent 单轮 `/api/agent/ask` | 意图路由 → ReAct 循环（Function Calling 调工具，≤5轮） | 3.6~3.9s |
| 多 Agent `/api/agent/orchestrate` | 路由 → 分派(DOCUMENT/STATS/REPORT) → HYBRID 组合 → 反思重写 | 3.4~18s |

### 离线入库
文档上传 → MinIO 存储 → PDFBox/POI 解析 → 滑动窗口分块(512字+64重叠) → 智谱 Embedding → Milvus 存向量（**实测：242 块向量化 4.06s，≈60 块/秒**）

## 四、关键技术决策

| 决策 | 理由 |
|------|------|
| 模块化单体（5 模块） | 规模无需微服务；模块边界清晰可演进；央国企主流回退方向 |
| MyBatis-Plus | 国内生态、SQL 可控、LambdaQueryWrapper、无 N+1 |
| Milvus 2.5（升级自 2.4.10） | 内置 BM25 Function（服务端自动稀疏向量）；v1 API 兼容 |
| v1 + v2 双客户端共存 | v1 管稠密路（search/insert），v2 管 BM25 建表/稀疏检索（`FunctionType.BM25`+`EmbeddedText`） |
| deepseek-v4-flash（思考模型） | Function Calling 需回填 `reasoning_content`；消息带 `type` 字段（2026-08 实测适配） |
| 三层降级矩阵 | Rerank 失败→原分排序；混合检索失败→纯稠密；记忆/评审失败→静默；LLM 挂→熔断(5次/60s) |

## 六、部署拓扑

- Docker Compose 5 容器：MySQL(3307) / Milvus 2.5.16(19530+9091) / Milvus-etcd / Milvus-minio(9001) / MinIO(9000+9002)

- 配置外置：`.env` 环境变量（JWT_SECRET / ZHIPU_API_KEY / DEEPSEEK_API_KEY）+ `application.yml` + `@ConfigurationProperties(RagProperties)`
