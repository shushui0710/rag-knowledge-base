## 二、本次发现并修复的问题（真实运行暴露）

| # | 类型 | 问题 | 根因 | 修复 |
|---|------|------|------|------|
| 1 | 🔧 缺陷 | 上传文档报 `Unknown column 'category'` | 旧 MySQL volume 残留旧表结构（init.sql 有 category，但 `IF NOT EXISTS` 对已存在库不生效） | 对运行库执行 `ALTER TABLE document ADD COLUMN category`（migration_week6.sql） |
| 2 | 🔧 缺陷 | 删除不存在的文档返回 success | `DocumentServiceImpl.delete` 无存在性校验（逻辑删除影响 0 行仍返回成功） | 加 `selectById` 存在性校验 → 400"文档不存在" |
| 3 | 🔧 缺陷 | 向量检索报 `Search target vector type is illegal` | **Milvus 2.5 SDK 升级**：FloatVector 查询向量必须 `List<Float>`，传 `float[]` 报错（2.4 时代可传） | `search()/searchMemory()` 增加 `toVectorList()` 转换 |
| 4 | 🔧 缺陷 | Agent 工具调用报 400 `missing field type` / `reasoning_content must be passed back` | **deepseek-v4-flash 思考型模型**：每条消息须带 `type` 字段；assistant(tool_calls) 消息必须原样回填 `reasoning_content`+完整 tool_calls（含 index/type） | `LlmService` 用 `readTree` 从原始 JSON 取消息 + 补 `type`；`AgentExecutor` 消息补 `type` 字段 |
| 5 | 🔧 缺陷 | `/api/auth/me` 恒报"用户未登录" | `WebMvcConfig` 排除 `/api/auth/**` 把 me 也放行了（UserContext 未设置） | 精确排除 `/api/auth/login` + `/api/auth/register` |
| 6 | 🔧 缺陷 | 空问题返回 200（走检索兜底） | `ChatController.ask` 用 `@RequestBody String` 接整个 JSON，无法校验 question 字段 | DTO 化（`AskRequest{question}`）+ 空校验 → 400 |
| 7 | 📝 观察 | "有哪些文档"被路由到 DOCUMENT，检索无关段落导致 **LLM 幻觉编造文档列表** | 路由 prompt 对"列表/统计"类意图识别不准 | 增强 Router prompt（列出/有多少/有哪些 → STATS），复测通过 |
| 8 | 📝 观察 | 低相关重复文本 score 超阈值 0.35 未被过滤（LLM 诚实拒答"无相关信息"） | min-score 未按测试集校准 | 可接受（防幻觉 OK）；建议上线前用测试集校准阈值 |

## 六、遗留事项（非阻塞）

3. **Rerank/改写未在运行中触发**：因混合检索 collection 未重建（走稠密降级）；重建后可复测精排效果
