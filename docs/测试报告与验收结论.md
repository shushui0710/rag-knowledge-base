## 五、边界条件与潜在缺陷审查

### 5.1 已覆盖的防御（降级矩阵）

| 风险点 | 防御策略 | 位置 |
|--------|----------|------|
| Rerank API 失败 | 降级按原分数排序取前 N | RerankServiceImpl |
| 混合检索稀疏路失败（collection 未重建） | 降级纯稠密检索 | MilvusService.hybridSearch |
| 查询改写失败 | 返回原问题兜底 | QueryRewriterServiceImpl |
| 记忆保存/召回失败 | 静默降级（不阻断主流程） | MemoryServiceImpl |
| 评审调用失败/解析失败 | 默认放行 | CriticServiceImpl |
| 工具执行异常 | 错误文案回填给 LLM 继续 | AgentExecutor |
| LLM 服务不可用 | 熔断（连续 5 次失败 → 开 60s）| LlmCircuitBreaker |
| 空值 | 参数/响应/索引越界判空 | 各 Service/工具 |

### 5.2 并发与资源安全

| 检查项 | 结论 |
|--------|------|
| ThreadLocal 泄漏 | ✅ `UserContext.clear()` 在拦截器 `afterCompletion` 调用（成功/异常均执行） |
| Embedding 缓存并发 | ✅ ConcurrentHashMap + 容量上限 5000（超限清空） |
| 记忆主键并发 | ✅ AtomicLong 自增 |
| 工具注册表并发 | ✅ 懒加载 double-check + toConcurrentMap |

### 5.3 已知注意事项（非缺陷）

1. **混合检索需重建 collection**：旧 collection 由 v1 创建（无 `bm25_vector`/BM25 Function），升级后需 drop 重建并重新入库，否则 `hybridSearch` 自动降级为稠密检索。
2. **TODO 1-2 阈值过滤未实现**：标准答案已写入 `ChatServiceImpl.ask()` 注释，可按需补上（默认 0.35）。
3. **外部依赖**：Rerank/Embedding/LLM 均依赖第三方 API 可用性与配额（均已做降级）。
4. **日志级别**：`logging.level.com.liushuwen.rag: debug` 便于演示，生产建议调为 info。
