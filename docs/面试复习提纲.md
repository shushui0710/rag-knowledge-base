## 一、项目一句话介绍

"我做了一个基于 RAG 的智能知识库问答系统，用户上传文档后系统自动解析、分块、向量化存入 Milvus，提问时通过语义检索 Top-K 片段，拼入 Prompt 调大模型生成带来源引用的回答。后端用 Spring Boot 模块化单体，前端 Vue3，认证用 JWT + BCrypt，多用户数据隔离。"

**如果追问细节，展开顺序**：架构选型 → 离线流程 → 在线流程 → 认证体系 → 一个亮点

## 二、技术选型一句话理由

| 选型 | 为什么 |
|------|--------|
| MyBatis-Plus 而非 JPA | SQL 完全可控，LambdaQueryWrapper 动态查询方便，国内主流 |
| 模块化单体而非微服务 | 项目规模不需要分布式开销，模块边界清晰为未来演进预留 |
| Milvus 而非 ES | 向量检索是 RAG 核心，Milvus 专为高维向量设计，ES 做向量是后来加的 |
| 智谱 embedding 而非 OpenAI | 国内访问稳定，2048 维精度够用，免费额度够开发 |
| DeepSeek 而非 GPT | 国内合规，OpenAI 兼容格式，成本低 |
| JWT 而非 Session | 无状态，前后端分离天然适配，不依赖服务端内存 |
| BCrypt 而非 MD5 | 自带盐值防彩虹表，计算慢是特性（防暴力破解） |
| Pinia 而非 Vuex | Vue3 官方推荐，API 更简洁，TS 支持更好 |

## 三、RAG 流程速记

### 离线（文档入库）

```
上传文件 → MinIO存原件 → PDFBox/POI解析出文本 → 滑动窗口分块(512字+64重叠)
→ 智谱API批量Embedding(2048维) → Milvus插入向量+MySQL存元数据
```

### 在线（智能问答）

```
用户提问 → 智谱API向量化 → Milvus检索Top-5 → 编号拼接Prompt → DeepSeek生成
→ 解析回复 → 构建sources JSON → 存回答到MySQL → 前端Markdown渲染
```

### 关键参数

| 参数 | 值 | 为什么 |
|------|-----|--------|
| chunk_size | 512 字符 | 太小丢上下文，太大检索不准 |
| chunk_overlap | 64 字符 | 防止关键信息被截断在边界 |
| top_k | 5 | 召回足够上下文又不超 token 限制 |
| dimension | 2048 | 智谱 embedding-3 的输出维度 |

## 四、10 个面试亮点

### 亮点1：JSON 解析从手动遍历优化为 POJO 绑定

**一句话**：解析智谱 API 响应时，从手动遍历 JsonNode 改为 Jackson POJO 绑定。

**展开**：定义 EmbeddingResponse/EmbeddingItem 两个 POJO，用 `@JsonIgnoreProperties(ignoreUnknown = true)` 忽略多余字段，`objectMapper.readValue(json, EmbeddingResponse.class)` 一行搞定。

**追问预案**：
- "手动遍历也能跑啊？" → 可读性差、维护成本高、字段名写错不报错
- "POJO 绑定有什么风险？" → API 返回结构变了会反序列化失败，但 ignoreUnknown 缓解了这个问题

### 亮点2：@JsonIgnoreProperties 防御第三方 API 变更

**一句话**：用 `ignoreUnknown = true` 让 POJO 只解析需要的字段，第三方 API 加字段不会导致反序列化失败。

**追问预案**：
- "和 `@JsonInclude` 有什么区别？" → ignoreUnknown 是反序列化时忽略多余字段，JsonInclude 是序列化时控制输出哪些字段

### 亮点3：用 LinkedHashMap 保证 JSON 字段顺序

**一句话**：构建 API 请求体时用 LinkedHashMap 而非 HashMap，保证 JSON 字段顺序与 API 文档一致。

**展开**：HashMap 无序，JSON 字段顺序不可控，虽然 HTTP 不要求顺序，但便于调试和排查问题。

### 亮点4：幂等设计防止重复向量化

**一句话**：embed() 方法先检查 document.embedding_status，已完成的直接返回，防止重复调用。

**追问预案**：
- "并发请求同时进来怎么办？" → 当前是应用层幂等，生产环境可加分布式锁或数据库唯一索引
- "为什么不用状态机？" → 当前三态（未开始/进行中/已完成）用枚举足够，没必要引入复杂状态机

### 亮点5：解决 Milvus SDK 的 Gson/FastJSON 依赖冲突

**一句话**：Milvus Java SDK 依赖 Gson，项目用 Jackson，插入向量时 Gson 序列化格式与 Jackson 不一致，改为统一用 Gson 处理 Milvus 相关数据。

**追问预案**：
- "为什么不统一用 Jackson？" → Milvus SDK 内部用 Gson，改不了第三方库
- "FastJSON 有什么问题？" → Milvus v2 SDK 用的 Gson 序列化，FastJSON 的行为不一致

### 亮点6：解决 Milvus v1/v2 API 混用

**一句话**：Milvus 有 v1（毫秒超时参数）和 v2（纳秒超时参数）两套 API，文档混在一起容易用错，我在实践中发现并统一使用 v2 API。

### 亮点7：RestTemplate 和 ObjectMapper 改为 @Bean 注入

**一句话**：将 `new RestTemplate()` 和 `new ObjectMapper()` 改为 Spring 容器管理的 @Bean，通过构造注入使用。

**展开**：RestTemplate 用 RestTemplateBuilder 设置连接超时 10s + 读取超时 60s；ObjectMapper 不需要自己写 @Bean，Spring Boot JacksonAutoConfiguration 已自动配置含 Java8 时间模块 + FAIL_ON_UNKNOWN_PROPERTIES=false。

**追问预案**：
- "new 出来也能跑啊？" → ①超时不可控（默认无超时会一直等）②难以测试（mock 困难）③ObjectMapper 重复创建浪费资源
- "ObjectMapper 为什么不用自己写 @Bean？" → Spring Boot 已自动配置好了，自己写反而覆盖默认行为

### 亮点8：RAG 在线流程编排 — 先存问题再做后续

**一句话**：ask() 方法先存用户问题到数据库，再执行向量化+检索+生成，即使后续失败也有问题记录。

**追问预案**：
- "为什么不全部成功再一起存？" → 数据优先原则，用户问题是最有价值的，即使后续流程失败也有据可查
- "如果存问题就失败了怎么办？" → 直接抛异常返回错误，用户会重试

### 亮点9：Markdown 渲染的 XSS 防护

**一句话**：前端用 markdown-it 渲染大模型回复，配置 `html: false` 阻止原始 HTML 标签直接渲染，防止 XSS 注入。

**追问预案**：
- "html:false 够吗？" → markdown-it 默认转义 HTML，如果不放心可以加 DOMPurify 二次过滤
- "大模型会输出恶意 HTML 吗？" → 大模型本身不会，但如果检索的文档里被注入了恶意脚本，可能被带进输出

### 亮点10：JWT 认证体系 — ThreadLocal + 拦截器

**一句话**：JwtInterceptor 拦截请求解析 token 提取 userId，存入 ThreadLocal，Service 层通过 UserContext.getUserId() 获取当前用户，实现数据隔离。

**追问预案**：
- "ThreadLocal 会不会内存泄漏？" → 会在请求结束时 afterCompletion 里 clear，但如果用线程池，用完不清理会泄漏，所以一定要在 afterCompletion 中 clear
- "为什么不用 Spring Security？" → 项目规模不需要，JWT + 拦截器够用且更轻量，引入 Spring Security 学习成本高
- "token 过期了怎么办？" → 前端 axios 拦截器收到 401 自动跳转登录页

## 五、高频考点速查

### RAG 核心

| 问题 | 回答要点 |
|------|----------|
| 什么是 RAG？ | 检索增强生成，先检索相关文档片段再喂给大模型，减少幻觉 |
| 为什么要分块？ | 大模型上下文有限，整篇文档塞不进去，分块后只检索相关片段 |
| 滑动窗口分块是什么？ | 固定大小窗口 + 重叠部分，防止关键信息被截断在边界 |
| Top-K 检索为什么不用全文搜索？ | 语义检索找的是"意思相近"而非"字面匹配"，向量距离比关键词匹配更准 |
| Prompt 怎么拼？ | 系统角色设定 + 检索到的片段（编号）+ 用户问题，让模型基于资料回答 |

### Spring Boot

| 问题 | 回答要点 |
|------|----------|
| @Configuration 和 @Bean 的区别？ | @Configuration 标记配置类，@Bean 标记方法返回值交给容器管理 |
| @Autowired 和构造注入的区别？ | 构造注入在对象创建时就完成依赖注入，不可变（final字段），更推荐 |
| @Value 和 @ConfigurationProperties？ | @Value 单个值，@ConfigurationProperties 批量绑定 + 松散匹配 |
| 全局异常处理怎么做的？ | @RestControllerAdvice + @ExceptionHandler，捕获 BusinessException 返回统一 Result |
| MyBatis-Plus 逻辑删除？ | deleted=1 标记删除，查询自动过滤，数据不丢失 |
| 自动填充怎么实现的？ | MetaObjectHandler 实现 insertFill/updateFill， createTime/updateTime 自动赋值 |

### 认证与安全

| 问题 | 回答要点 |
|------|----------|
| JWT 三段结构？ | Header(算法) + Payload(claims) + Signature(签名)，Base64 编码 |
| BCrypt 为什么安全？ | 自带随机盐值，同密码每次加密结果不同，防彩虹表；计算慢是特性防暴力破解 |
| ThreadLocal 原理？ | 每个线程有自己的副本，互不干扰；afterCompletion 必须 clear 防泄漏 |
| 数据隔离怎么做的？ | 拦截器提取 userId 存 ThreadLocal，Service 层查询时用 LambdaQueryWrapper 加 userId 条件 |
| 前端路由守卫？ | router.beforeEach 检查 token，无则跳登录页 |

### 前端

| 问题 | 回答要点 |
|------|----------|
| Vue3 Composition API vs Options API？ | 逻辑关注点可聚合，复用性强，TS 支持好 |
| Pinia vs Vuex？ | 官方推荐，无 mutation，更简洁 |
| nextTick 干嘛的？ | 等 DOM 更新后再执行回调，用于操作更新后的 DOM |
| v-html 有什么风险？ | XSS，所以要 html:false 或 DOMPurify 过滤 |
| deep watch 和普通 watch？ | deep:true 深度监听对象内部变化，性能开销大，按需使用 |

## 六、容易被追问的坑点

### 1. Milvus standalone 模式有 bug

standalone 模式（单容器）有已知 bug，改为多容器模式：etcd + milvus-minio + milvus 三个容器。

### 2. Milvus 向量插入格式

Milvus SDK 用 Gson 序列化，如果用 Jackson/FastJSON 构建的数据格式不兼容，插入会失败。统一用 SDK 要求的格式。

### 3. 智谱 embedding 维度

智谱 embedding-3 输出 2048 维，application.yml 中 milvus.dimension 必须设为 2048，否则建集合时维度不匹配。

### 4. DeepSeek API 格式

DeepSeek 是 OpenAI 兼容格式，请求体结构：`{model, messages: [{role, content}]}`，响应：`{choices: [{message: {content}}]}`。和智谱 Embedding API 调用方式几乎一样。

### 5. Spring Boot ObjectMapper 自动配置

Spring Boot 已经通过 JacksonAutoConfiguration 注册了一个 ObjectMapper @Bean，默认配置了 Java8 时间模块和 `FAIL_ON_UNKNOWN_PROPERTIES=false`。不需要自己写 @Bean，自己写反而覆盖默认配置。

### 6. MyBatis-Plus @MapperScan 通配符

`@MapperScan("com.liushuwen.rag.**.mapper")` 用通配符扫描所有模块的 mapper 目录，模块化单体不需要每个模块单独配。

### 7. Docker 凭证问题

Git Bash 中拉 quay.io 镜像可能遇到凭证问题，用 `DOCKER_CONFIG=/tmp/docker-config docker pull` 绕过。
